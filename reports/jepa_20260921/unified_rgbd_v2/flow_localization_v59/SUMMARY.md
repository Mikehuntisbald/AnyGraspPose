# V59：flow 定位误差拆解

冻结 V56 checkpoint（SHA256 `044a8f928d324e54c8e2cab2927dd31e55942cde98bc09fa5f18ce5245d0fa5f`），训练分区中物理序列隔离的 256 帧，10°/60° 受控初始旋转。每帧比较相同输入、相同权重的恢复反馈开/关；没有训练、native val 或 official test。仅新增诊断输出，没有更改模型参数或预测运算。

## 已证实

- 10°、请求重遮挡、人工遮挡的原可见区域，62 个有效帧 / 982 点：零 flow EPE 4.976px；第一轮 7.930px；第二轮 5.766px；关闭恢复反馈 7.896px。**恢复帮助匹配，但匹配仍未稳定超过初始位置。**
- 同一条件第二轮粗匹配 5.778px，局部修正后 5.766px。只有 2.3% 的点超出每轴 ±14px 修正范围。因此，小误差下不能把主要问题归咎于修正范围太小；局部头的特征/优化能力需要单独验证。
- 60°、请求重遮挡、原可见人工遮挡区域，59 帧 / 629 点：零 flow 30.055px，最终 28.623px；71.2% 的点在粗匹配后超出 ±14px 修正范围。即使有 oracle 最佳修正，此限制仍留下 15.114px 的平均误差下界。
- 60°上述区域恢复反馈使 EPE 从 28.186px 变成 28.623px，因此反馈不能无条件增强。
- `endpoint` 输入包含 source/matched descriptor、CAD XYZ 和 source UV，但不直接包含 coarse UV、匹配位移或局部相关分布。是否这是局部修正无效的原因尚需匹配训练对照，不能从代码直接认定。

## 下一步的设计约束

优先做局部对应细化的匹配对照：补充估计位移、局部相关和原始观测证据，并以显式像素对应训练；区分单纯训练不足与输入信息不足。大误差另外需要多尺度粗匹配。恢复反馈保留实际观测约束。

不要仅放大 flow 写入：V56 已有同权重 no-transport 几何对照，重遮挡真实 XYZ 8.695→8.699mm、深度 7.617→7.616mm，几乎不变。这是旧 V56 样本结果，不是本轮 256 帧的几何评分；它说明双向连接存在并不等于重建已经消费了对应。

几何准确目标尚未达到。没有改默认模型，也没有把 oracle 下界或受控 flow 指标当成几何/位姿验收。
