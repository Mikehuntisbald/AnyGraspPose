# Audited upstream contracts

Snapshot identities are in `upstream/versions.json`. The snapshots and licenses are retained for audit; no upstream hand layer is imported or copied into the training implementation.

- DexYCB toolkit `64551b001d360ad83bc383157a559ec248fb9100`: `dex_ycb.py` defines s0/s1, 100 sorted sequences per subject, eight serials, `ycb_grasp_ind`, `ycb_ids`, and `pose_y` indexing. Its `grasp_eval.py:278` converts aligned depth to meters by division by 1000. The pinned README lists subject 01's first five sorted sequences, so positions 0..3 are independently known s0 train members; position 4 is val and is excluded from the recovered subset. `sequence_loader.py` documents raw aligned depth in millimeters. FPS is explicitly 30 from the official paper, section 2.1 (retained as `upstream/chao_cvpr2021.pdf`); no per-frame hardware timestamps are present in the indexed release.
- FoundationPose `a1b694b83e633c2cb6115b9063d940a687759392`: `estimater.py:82` returns translation by negative mesh center. `pose_last` is internal centered pose; `track_one` accepts `(rgb, depth, K, iteration, extra={})`, and returns `(pose @ get_tf_to_centered_mesh()).cpu().numpy().reshape(4,4)`. The adapter sets the correct CUDA current device, shape and float32 dtype and restores prior state after rejection or an exception. No real FP weights were provided.
- nvdiffrast `253ac4fcea7de5f396371124af597e6cc957bfae`, installed version 0.4.0: CUDA context and triangle rasterization were exercised against the independent CPU rasterizer for depth and centered XYZ. The OpenCV image convention is implemented at the clip-space boundary; no model-state axis conversion is hidden downstream.
- torchvision 0.23.0+cu128 / torch 2.8.0+cu128 are the actual remote installations. ResNet50 ImageNet V2 weights are from the official PyTorch download, with complete SHA256 in `upstream/rgb_weights.json`.

Raw depth, mesh vertices and pose translation have **separate** scale factors. Defaults are 0.001, 1, and 1 respectively. Defaults only become verified for a data instance after its geometry audit passes. The render-depth audit uses target visible segmentation exclusively for metrics, never for input masking.

The bounded real-data preflight recovered a sequence from already-completed chunks of the official archive without editing the archive. Calibration and the target CAD came from the third-party HF complement repository through hf-mirror.com. The full asset archives were SHA256-checked against their HF LFS metadata, and their coordinate/scale consistency was checked with the recovered RGB-D sequence. These checks are not an assertion of a publisher-provided checksum. The exact source and hashes are in `cache/assets/receipt.json` on the remote workspace and the copied run receipts.
